# 流式增量 BPE 的合并与结算策略：尾段 O(n log n) 堆合并 + 按半径 K 结算

2026-08-29 随 v0.3 实施。状态：已接受并实施。

## 决策

流式增量分词对每帧的新增码元，采用两段式处理：

1. **合并**：尾段内用 `bpeMerge` 的 O(n log n) 最小堆合并，自 v0.3 引入，替代旧的 O(n²) 朴素全扫；合并只发生在段内，跨段不合并。
2. **结算**：每帧末把「已越过合并半径 K 的左侧完整段」立即 pop 输出，尾部保留区恒 ≥ K 码元；K = 最长 token 码元数，本词表实测 128，即合并影响的半径上界。

两者合起来构成当前可达的最优增量形态：正确性由逐 token 对拍钉死，性能为此约束下的上限。

## 背景与理由

- **动机一：合并从 O(n²) 降到 O(n log n) 有量化依据**。旧朴素每轮全扫找最小 rank 相邻对，对超长段是平方级；v0.3 用 `bpeMerge` 的最小堆 + 邻接双链表 + 惰性删除，每节点至多合并一次、每 pair 进出堆 O(log n)，总 O(n log n)。
- **动机二：结算按半径 K 是正确性边界，不是性能方案**。BPE 合并只影响相邻码元，合并半径 ≤ 最长 token 码元数 K。尾部保留 ≥ K 即与未来帧绝缘，左侧按完整段 pop，不从中切刀，不破坏合并轨迹。
- **动机三：O(log K)/帧做不到是硬约束，不是实现难度**。增量合并堆的「跨帧延续」依赖 pre 段边界稳定，但段边界随帧动态重构——段断时已合并且跨边界的产物必须打断重排，延续的堆立即失效退回重扫，故单帧无法压到 log K。

## 被否决的选项

- **候选方案二：跨帧延续合并堆的「真增量」，单帧 O(log K)**。被否决：依赖段边界稳定这一前提，而流式的 pre 段边界本就动态重构，延续堆在段断时必须打断重排，无法维持；实现不可行，不是写法问题。
- **候选方案三：朴素 O(n²) 全扫合并**。被否决：超长段平方级退化成死循环，为早期事故，v0.3 的堆实现已替代它，不做回退。

## 结论

流式增量 BPE 的合并与结算策略锁定为「尾段 O(n log n) 堆合并 + 按半径 K 结算、pop 已稳定 token 并保持保留区 ≥K」。正确性已由 12 个 golden 测例逐 token 对拍与 3 种大数据形态精确一致双重验证；性能为当前架构下的上限——比朴素 O(n²) 大幅改善，但未达 O(log K)/帧，那个目标因段边界动态重构而不可行。
